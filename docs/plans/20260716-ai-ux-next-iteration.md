# AI-ввод расхода: бэклог на следующую итерацию UX

Отложено осознанно (обсуждено 2026-07-16). Сделано в текущей итерации: живая
транскрипция при записи, отмена записи жестом вверх, подсветка изменений после
голосовой правки + «Отменить», хептики/тост алиаса, камера первым действием.

## 1. Анимация «чек печатается»
После распознавания строки чека выезжают последовательно сверху вниз, как из
принтера (staggered появление строк ReceiptView), c success-хептиком в конце.
Доводит метафору бумажного чека (перфорация уже есть) до фирменного момента.
- Реализация: `ReceiptView` — параметр `animateIn: Bool`, каждая строка с
  `.transition(.move(edge: .top).combined(with: .opacity))` и задержкой
  `Double(index) * 0.06`; включать только при получении НОВОГО черновика
  (не при правке позиции). Уважать `accessibilityReduceMotion`.

## 2. Вопросы модели — чипы-ответы
Вопрос «Кто платил?» сейчас просто текст. Под вопросом рисовать чипы
участников — тап отвечает без голоса (локально проставляет donorId) или шлёт
текстовую правку в /parse.
- Сервер уже умеет text-правку (`text` part + draft).
- Сложность: понять тип вопроса. Дешёвый вариант — сервер возвращает
  структурированный вопрос `{text, kind: "payer"|"price"|"other", itemIndex?}`
  (расширить responseSchema), клиент рисует чипы только для известных kind.

## 3. Фото чека: превью-чип приложенного фото
После отправки фото оно «исчезает в никуда». Показывать маленький thumbnail-чип
«чек приложен» над формой (тап — посмотреть), чтобы было видно, из чего
распознано. Данные уже есть в `ReceiptCapture.imageData`.

## 4. Нюдж после «только фото»
Фото без голоса даёт позиции на всех поровну. После такого результата показать
подсказку «Зажмите микрофон и скажите, кто что брал» — превращает фото+голос в
очевидный сценарий. Условие: `didRecognize && hasDraftItems && все доли равные
&& распознано из image без audio`.

## Грабли: латентность нажатия — SwiftUI DragGesture (решено 2026-07-17)
Отклик hold-to-talk микрофона опаздывал на ~100-300 мс; на коротком тапе
события приходили пачкой на отпускании («микроанимация после release»).
Причина — НЕ рендер и НЕ аудиодвижок: `DragGesture(minimumDistance: 0)`
проходит арбитраж распознавания жестов, и первый `onChanged` задерживается.
Решение — `MicTouchSurface` (прозрачный `UIControl` через UIViewRepresentable):
`beginTracking` вызывается прямо из `touchesBegan` без арбитража. Замеры
(os_log subsystem `com.zagir.splitty`, category `latency`): доставка ~25 мс,
видимый отклик ~45 мс от касания. Вывод на будущее: для мгновенных
press-откликов в SwiftUI использовать UIKit-поверхность, не жесты.

## 5. Прод-долги (не UX)
- Отозвать текущий GEMINI_API_KEY (засвечен в чате) и завести новый.
- UI-тесты DemoFlow/OfflineSmoke падают без локального сервера — поднять
  их стенд или пометить skip-условием.
- Закоммитить iOS-изменения текущей итерации на feature/ios-app (ждём
  подтверждения владельца после ручного теста).
