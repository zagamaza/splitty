## Solution Overview

Три сквозных решения, которые определяют форму правок:

**Совместимость со старыми сборками — жёсткое ограничение.** У людей на руках версии, которые не шлют новых полей. Сервер обязан принимать запросы без них. Ужесточать контракт можно только там, где это не ломает установленное.

**Атомарность — условиями в фильтре, а не блокировками.** Транзакций нет (mongo одним узлом), и это не изменится в рамках плана. Все конкурентные правки идут через `UpdateOne` с условием в фильтре и проверкой `MatchedCount`.

**Мягкое удаление вместо физического.** Статус `archive` в модели уже есть и используется ботом; нормализация скрывает такие операции из всех чтений. Переход на него ничего не ломает и делает удаление обратимым.

## Technical Details

- `Operation` получает `version int` (bson `version`), растущий через `$inc`; правка требует совпадения версии в фильтре
- `handleJoinRoom` перед вступлением читает запись приглашения и отклоняет `left`/`declined` без свежего `pending`
- `clientOpId` для расхода поднимается на уровень формы: живёт, пока не меняется содержимое, и переживает повтор после 5xx
- денежные поля Android переводятся `Int` → `Long`; на iOS `Int` уже 64-битный
- iOS-очередь получает `schemaVersion` и не помечается загруженной при неудачном разборе
